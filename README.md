# 🎭 Quantise AI Simulator

Интерактивный тренажер бизнес-переговоров для отработки навыков коммуникации по методологиям SPIN и Гарвардского переговорного метода. 

Приложение представляет собой рабочую платформу с асинхронным бэкендом на **FastAPI**, реляционной СУБД **PostgreSQL** для хранения аналитики и интерфейсом на чистом JavaScript (Vanilla JS). Реализована гибридная архитектура работы с искусственным интеллектом для стабильного деплоя в облачных средах.

🌐 **Ссылка на работающее приложение:** [https://quantise-hackathon.onrender.com](https://quantise-hackathon.onrender.com)

---

## ✨ Основные возможности платформы

*   🧠 **Гибридная обработка ИИ-запросов (Ollama ↔️ Hugging Face ↔️ Автономный фолбек):** Бэкенд поддерживает умную маршрутизацию. При локальном запуске система приоритетно обращается к локальной модели Qwen через Ollama. В облачном окружении (Render), где локальный запуск нейросетей ограничен по ОЗУ, сервер автоматически переключается на работу с моделью **Qwen 2.5 7B Instruct** через бесплатный Inference API от Hugging Face. При сбоях сети или превышении лимитов активируется встроенный текстовый генератор контекстных ответов, что гарантирует работу симулятора без ошибок.
*   📊 **Аналитика сессий (Дашборд):** В конце каждого сценария ИИ-клиент оценивает навыки игрока по 5 ключевым метрикам: *Аргументация, Вежливость, Четкость, Эмпатия и Гибкость*. Данные сохраняются в базу данных.
*   👤 **Личный кабинет игрока:** На странице профиля рассчитывается средняя статистика по всем завершенным сессиям пользователя, отображается винрейт и определяется преобладающий стиль ведения переговоров (*Аналитик, Боец, Дипломат или Харизматик*).
*   🔄 **Динамическая навигация:** Интерфейс проверяет статус авторизации пользователя в `localStorage`. На главной странице и в меню выбора сценариев кнопки «Вход» и «Регистрация» автоматически заменяются на переход в «Профиль», если сессия активна.
*   🔒 **Режим гостя:** Симулятор можно протестировать без создания аккаунта. В этом случае параметры шкал рассчитываются только в памяти браузера, не отправляя логи в базу данных.

## 🚀 Вариант установки №1: Локальный запуск (Разработка)

### 1. Подготовка базы данных
Создайте пустую базу данных PostgreSQL (например, с именем `postgres`) на вашем локальном сервере СУБД.

### 2. Конфигурация окружения
В корневой директории проекта создайте файл **`.env`** и укажите параметры подключения к вашей БД, а также токен Hugging Face для работы облачного фолбека:
```env
DB_USER=postgres
DB_PASSWORD=ваш_локальный_пароль
DB_HOST=127.0.0.1
DB_PORT=5432
DB_NAME=postgres

# Токен для генерации ответов через Hugging Face в случае отсутствия Ollama
HF_TOKEN=hf_ваш_токен_из_настроек_huggingface
```

### 3. Развертывание локальной ИИ-модели (Опционально)
1. Установите утилиту **Ollama** на компьютер.
2. Скачайте модель через консоль: `ollama run qwen2.5:3b`.
3. Утилита останется работать в фоновом режиме на порту `11434`. Бэкенд автоматически распознает её при старте сессии.

### 4. Установка пакетов и запуск
Из корня проекта выполните последовательно:
```bash
# Установка необходимых библиотек
pip install -r requirements.txt

# Запуск веб-сервера
python -m uvicorn backend.main:app --reload
```
При первом запуске бэкенд самостоятельно создаст таблицы (`users`, `sessions`, `messages`) в PostgreSQL. Приложение станет доступно в браузере по адресу: **`http://127.0.0.1:8000`**.

## 🐳 Вариант установки №2: Запуск через Docker

Проект контейнеризирован и готов к запуску в изолированных окружениях.

### Вариант А: Использование готового образа из GitHub Packages (GHCR)
Воркфлоу автоматизации собирает проект при каждом обновлении ветки `main`. Вы можете развернуть готовую сборку:

```bash
# 1. Авторизация в реестре контейнеров GitHub (используйте ваш GitHub Personal Access Token)
echo "YOUR_GITHUB_TOKEN" | docker login ghcr.io -u YOUR_GITHUB_USERNAME --password-stdin

# 2. Запуск контейнера с передачей переменных окружения
docker run -d \
  -p 8000:8000 \
  --name quantise-production-app \
  -e DB_USER="postgres" \
  -e DB_PASSWORD="your_cloud_password" \
  -e DB_HOST="your_postgres_host" \
  -e DB_PORT="5432" \
  -e DB_NAME="your_db_name" \
  -e HF_TOKEN="hf_your_inference_api_token" \
  ghcr.io/YOUR_GITHUB_USERNAME/YOUR_REPO_NAME/quantise:latest
```

### Вариант Б: Локальная сборка образа
Если вам необходимо собрать образ вручную из локальных исходников, выполните из корня проекта:
```bash
# Сборка образа
docker build -t quantise-local .

# Запуск контейнера
docker run -d -p 8000:8000 --name quantise-instance quantise-local
```

## 🌐 Облачный деплой

Серверная часть и статика развернуты на платформе **Render** и подключены к базе данных Render PostgreSQL.
*   **Сборка:** Контейнер автоматически пересобирается платформой на основе предоставленного `dockerfile`.
*   **Безопасность данных:** Для безопасного соединения с СУБД активирован режим шифрования `PGSSLMODE=require`.
*   **Стабильность ИИ:** Переданный токен `HF_TOKEN` гарантирует бесперебойную генерацию реплик в облаке со средней скоростью ответа модели менее 1.5 секунд.
